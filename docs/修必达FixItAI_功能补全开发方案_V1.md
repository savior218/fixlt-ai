# 修必达 FixIt AI · 功能补全开发方案 V1

> 创建时间：2026-11-19
> 状态：方案评审稿（未开工）
> 上一份文档：《修必达FixItAI_工作进度与完成效果报告_V2.md》

## 一、背景

当前线上版本（https://fixlt-ai.onrender.com）核心诊断流程已闭环，但以下功能点仍为「演示状态」占位，点击后仅弹提示、无真实逻辑。本方案将这些占位逐一补全为可用功能。

| 功能点 | 现状 | 代码位置 |
|---|---|---|
| 图片上传 | 纯占位，点击只弹「演示状态」提示 | `frontend/src/pages/Diagnose.tsx`（上传卡片区） |
| 通知铃铛 | 按钮未绑定任何点击事件 | `frontend/src/components/TopBar.tsx` |
| 对接售后平台 | 「一键联系维修」只弹演示提示 | `frontend/src/pages/RepairAssistant.tsx` |
| 编辑资料 | 只弹「演示账号，编辑资料暂未开放」 | `frontend/src/pages/Settings.tsx` |
| 登录其他账号 | 无用户体系，账号为硬编码 `DEMO_USER`；后端有 user 表模型但无登录接口 | `frontend/src/types/user.ts` |
| 语音设置 | 开关/语速能保存，但朗读从未真正实现（全项目无 `speechSynthesis` 调用） | `frontend/src/pages/Settings.tsx` |

## 二、模块总览与实施顺序

| # | 模块 | 类型 | 依赖 | 优先级 |
|---|---|---|---|---|
| 1 | 用户登录体系（含编辑资料） | 前端+后端 | 无（地基） | ① 先做 |
| 2 | 报修工单闭环 | 前端+后端 | 依赖 #1 登录 | ② |
| 3 | 图片上传 + AI 看图 | 前端+后端 | 独立 | ③ |
| 4 | 语音播报（Web Speech API） | 仅前端 | 独立 | ④ |
| 5 | 通知中心（铃铛） | 仅前端 | 独立 | ⑤ |

排序逻辑：登录是所有数据归属的前提（工单、档案需挂在账号下），先做；语音与通知纯前端、互不依赖，靠后安排。

## 三、各模块设计

### ① 用户登录体系（地基）

**后端**

- user 表新增 `password_hash` 字段（bcrypt 哈希存储，绝不存明文）
- 新增 `app/api/auth.py`：
  - `POST /api/auth/register` 注册
  - `POST /api/auth/login` 登录，签发 JWT
  - `GET /api/auth/me` 获取当前用户
- JWT 鉴权：新增 `get_current_user` 依赖注入（放 `app/api/deps.py`），设备/维修/诊断接口逐步挂用户隔离
- 新增依赖：`pyjwt`、`passlib[bcrypt]`、`python-multipart`
- 种子数据归属一个内置演示账号，避免破坏现有 demo

**前端**

- 新增 `/login` 登录/注册页
- token 存 localStorage；API 封装统一携带 `Authorization` 头，401 自动跳登录页
- 路由守卫：无 token 重定向登录（保留游客/演示模式入口）
- 顶栏头像下拉菜单：昵称展示、编辑资料（改昵称/改密码）、退出登录
- 数据迁移策略：内置演示账号挂种子数据；新注册账号从空白开始；localStorage 草稿类数据不迁移

**关键约束**：保留「游客/演示模式」入口，不登录也能进入 Mock 演示（比赛硬约束：无 API 配置可离线演示）。

### ② 报修工单闭环

说明：客观上不存在可对接的真实第三方售后平台开放 API，本模块以「报修工单闭环」作为诚实替代方案。

**后端**

- 工单表（可复用/扩展现有 repair 模型）：创建工单、工单列表、状态流转接口
- 工单状态机：待受理 → 已受理 → 维修中 → 已完成

**前端**

- 报修助手页：「一键联系维修」改为「一键提交报修」→ 工单入库
- 维修记录页：工单状态跟踪条展示
- 降级：未登录时保留现有「复制报修说明」行为

### ③ 图片上传 + AI 看图

**前端**

- file input + 拖拽上传 → FileReader 本地预览 → canvas 压缩 → multipart 上传
- 限制：JPG/PNG、单张 ≤ 10MB

**后端**

- 接收图片转 base64 存储（比落盘更稳：Render 免费实例重新部署会丢失本地文件）
- `glm_client` 扩展为支持 OpenAI 兼容的 `image_url` 消息格式，模型切换 `glm-4v-flash`（免费、支持视觉），诊断 prompt 附带照片

**约束**

- Mock 模式：图片仅本地预览，不参与 AI 诊断（保持离线能力）
- 长辈模式：看图结论与文字诊断共用同一判断逻辑，仅文案表达不同

### ④ 语音播报（Web Speech API）

纯浏览器能力，免费无外部依赖：

- 新增 `utils/speech.ts`：`speak(text, rate)` / `stop()`；播放前先 cancel 当前 utterance
- 三个接入点：
  - AI 消息气泡加「朗读」按钮
  - `autoRead` 开启时新消息自动播报
  - 设置页「播放测试语音」真正出声
- 直接复用现有 prefs：`voiceEnabled`、`speechRate`，不新增设置项
- 边界：浏览器不支持时按钮隐藏/禁用并提示

### ⑤ 通知中心（铃铛）

第一版纯前端即可（通知天然是用户本地数据）：

- 新增 notifications zustand store，localStorage 持久化
- 通知产生点：诊断完成、高风险告警、工单状态变化
- 铃铛 → 下拉通知面板 + 未读数徽标 + 全部已读
- 后端通知表留作二期，不阻塞本期

## 四、统一约束（全程生效）

1. Mock 降级能力全部保留：无登录可游客演示、无 AI 配置走本地规则引擎
2. LLM API 密钥只在后端 `.env`，绝不进前端
3. 长辈模式只改文案不改判断逻辑；三端断点 lg(1024px) 规范不变
4. 不清空本地已有数据；localStorage 旧 key 保持兼容
5. 安全关键词拦截逻辑保留在前端本地，LLM 不参与风险判定
6. 进度文档按版本号递增存放于 docs 目录，不覆盖历史版本

## 五、验收口径（每模块完成后）

- 登录体系：注册 → 登录 → 编辑资料 → 退出 → 二次登录数据一致；游客模式可完整走 Mock 流程
- 工单闭环：提交工单 → 状态流转可见 → 未登录降级为复制说明
- 图片看图：上传/拖拽/预览/压缩正常；配 API 时看图诊断生效，未配 API 时仅预览
- 语音：朗读按钮出声、自动朗读生效、语速设置生效、不支持浏览器有提示
- 通知：三类通知可产生、徽标计数正确、面板已读逻辑正确
- 全程：生产构建零错误；390×844 / 768×1024 / 1440×900 三端视口回归通过
